Half-Life MMod and Brutal Half-Life together — what actually works

Mod compatibilityHalf-Life (GoldSrc)Updated 2026

On paper the combination is perfect. Brutal Half-Life adds weapons, gore and much larger ammo pools; MMod modernises the feel of the game and thickens up encounters. People have been trying to merge them for years.

They can't be merged, and it's worth understanding why — because once you know the reason, you'll also know why no guide, patch, or load order will ever fix it, and you can stop burning evenings on it.

The short answer: both mods ship their own compiled game libraries, and GoldSrc loads exactly one set per mod folder. Whichever set you copy in last is the mod you're playing. The other one is simply gone.

Why the merge fails

A GoldSrc mod folder can contain two kinds of thing:

  • Data — maps, models, sounds, sprites, text files. Inert. The engine reads it.
  • Code — compiled libraries in dlls\ and cl_dlls\. This is what defines how weapons fire, how enemies think, what the HUD does, how damage works.

When you launch a mod, the engine loads one server library and one client library — the ones in that mod's folder. There is no mechanism for chaining or layering them. Two mods that both define weapon behaviour are asking to be the same single library at the same time.

So when you copy MMod's files into Brutal Half-Life's folder, you overwrite Brutal's libraries with MMod's. The folder now contains Brutal's maps and models but MMod's code — which is to say, it's MMod with some stray files lying around. Reverse the copy and you get the mirror image. Either way one mod is gone.

This is also why the result is often worse than either mod alone: the surviving code references assets it doesn't expect and the loser's leftover files cause missing models, wrong sounds, and crashes on level load.

Why MMod is compatible with other mods

This is where the confusion comes from. MMod maintains a list of compatible mods and campaigns, so people reasonably assume Brutal Half-Life should be on it.

The distinction is code:

Campaign modsGameplay mods
ContainsMaps, models, soundsMaps, models, sounds + compiled libraries
ExamplesFan campaigns, level packsBrutal Half-Life, MMod itself
Compatible with MModYes — MMod supplies the code, the campaign supplies the levelsNo — both want to supply the code

A campaign mod is content looking for an engine to run on, so MMod can host it happily. Brutal Half-Life isn't content — it is an engine layer. Two of those don't stack.

The practical rule: if the mod folder has files in dlls\, it will not combine with MMod. That single check answers the compatibility question for any mod you're considering.

Three setups that do work

01 Both installed, switch between them

This is what most people actually want, and it takes seconds. The two mods live in separate folders and never touch each other:

Steam\steamapps\common\Half-Life\
    valve\
    bhl_v3\        <- Brutal Half-Life
    HL1MMod\       <- MMod

Switch by editing Half-Life's launch options (Properties › General › Launch Options) to point at the one you want:

-game bhl_v3
-game HL1MMod

Nothing is reinstalled, no files are overwritten, and each mod keeps its own saves.

02 MMod plus a campaign mod

If what you liked about Brutal was "more content", this is the productive direction. MMod's compatible-campaign list covers a lot of well-regarded fan campaigns, and those genuinely do run with MMod's improvements applied.

You get MMod's gameplay across new levels — which is a real combination, unlike the one you were trying to build.

03 Just pick one, deliberately

Less of a workaround than an honest recommendation. These mods pull in different directions and playing each on its own terms is better than a compromise that doesn't exist. See the comparison below.

What you can and can't copy across

People often follow up with "fine, can I at least take the weapon models?" Sometimes — with an important limit.

  • Sometimes portable: models, sprites, sounds, textures. These are data, and the engine will render whatever it's pointed at.
  • Never portable: behaviour. A weapon model copied across arrives as geometry only. Its firing rate, damage, reload animation timing and alt-fire all live in the compiled libraries you didn't bring with it.

So you can make MMod's shotgun look like Brutal's. You cannot make it act like it. If that sounds unsatisfying, it's the same wall the full merge hits, just at a smaller scale.

Frequently asked

Is there a patch that makes them work together?

No, and there structurally can't be one short of someone rewriting both mods into a single codebase. Any "combined" package you find is one of the two mods with the other's assets mixed in.

Does the 25th Anniversary update affect this?

It makes things worse but isn't the cause. The anniversary engine update broke a large share of GoldSrc mods outright — if Brutal Half-Life isn't starting at all, that's a separate problem with its own fix. See Brutal Half-Life won't work.

Can I have both installed without them interfering?

Yes. Separate folders, separate saves, no interaction. Only the -game launch option decides which one runs.

What if I already merged them and now everything is broken?

Delete both mod folders and reinstall each from its original archive. Your base Half-Life install is untouched — mods never write into valve. If you did extract something into valve, verify the game's files to repair it.
