How to install any GoldSrc mod correctly

ReferenceHalf-Life 1 / GoldSrcUpdated 2026

Half-Life 1 mods have used the same structure since 1998. Learn it once and every GoldSrc mod you ever install works the same way — and when one doesn't, you'll know which of four things to check instead of reinstalling at random.

The whole rule in one line: one folder, directly inside the Half-Life directory, with liblist.gam at its top level.

Where mods go

A GoldSrc mod goes inside the Half-Life installation directory — the folder that contains hl.exe and the valve subfolder. Normally:

Steam\steamapps\common\Half-Life\

Not in valve. Not in sourcemods. Beside valve.

The sourcemods folder is for Half-Life 2. It belongs to the Source engine and a GoldSrc mod placed there will never be detected. This mix-up is behind a large share of "the mod didn't install" reports — see our side-by-side comparison of the two layouts.

The folder structure

A correct install looks like this:

Steam\steamapps\common\Half-Life\
    hl.exe
    valve\              <- the base game, don't touch
    modname\            <- the mod, one folder
        liblist.gam     <- must be here, at the top level
        maps\
        models\
        sound\
        sprites\
        dlls\           <- server code, if the mod has any
        cl_dlls\        <- client code, if the mod has any

Not every mod has all of these. A campaign mod might ship only maps and liblist.gam; a gameplay overhaul will have dlls and cl_dlls as well. That difference decides whether it can coexist with other mods — a mod with dlls cannot combine with another one.

The nesting mistake

This is the single most common install error, and it looks completely fine at a glance.

Extracting an archive with "extract to folder name" often produces a wrapper folder:

Half-Life\modname\modname\liblist.gam     <- broken
Half-Life\modname\liblist.gam            <- correct

The engine looks inside modname, finds another folder instead of the files it expects, and gives up. Nothing errors, nothing logs — the mod simply never appears.

The test: open the mod folder. If you see liblist.gam, you're done. If you see a single folder with the same name, move its contents up one level and delete the empty wrapper.

What liblist.gam does

It's the mod's manifest — a plain text file the engine reads to learn what it's loading. It defines the mod's display name, which libraries to load, and how it presents itself.

You rarely need to edit it, but knowing it exists is useful for two reasons:

  • It's the reliable install test. Its position tells you instantly whether the folder depth is right.
  • It tells you the mod's type. Open it in a text editor: if it names game libraries, the mod ships code and won't combine with other gameplay mods.

The two ways mods launch

This trips people up because mods don't all launch the same way, and the guides rarely say which kind you're dealing with.

A Steam library detection

Steam scans for installed GoldSrc mods when the client starts, and lists what it finds as separate library entries.

Because the scan only happens at startup, a mod copied in while Steam is running will not appear. Fully quit Steam — exit from the system tray icon, not just close the window — then start it again.

B The -game launch parameter

Some mods aren't designed for library detection at all and are launched by telling Half-Life to start them. In Half-Life's Properties › General › Launch Options:

-game modname

The name must match the folder exactly. Launch Half-Life and it boots into the mod.

Clear this line when you're done. While it's there, Half-Life always starts the mod — which people then report as "I can't play the normal game any more."

If a mod's own instructions specify -game, use that. An empty Steam library is expected behaviour for those mods, not a failed install.

The engine version problem

One thing has changed about GoldSrc modding in twenty-five years, and it's recent.

The 25th Anniversary update rebuilt significant parts of the engine, and a large share of mods built against the older one stopped working. If a mod is installed correctly and still won't run, this is the likely reason.

Two fixes, in order:

  1. Look for a compatibility patch. Many maintained mods released one. Better than the alternative, because your install stays current.
  2. Use the legacy engine. Valve archived the older build as the steam_legacy beta branch — but read what you give up before switching.

Removing a mod

Delete the mod's folder. That's all.

Because a correct install never writes outside its own folder, removal leaves no trace and the base game is untouched. Two things to remember:

  • Clear the -game launch option if you set one.
  • Restart Steam to drop the library entry.

If you extracted mod files directly into valve at some point, that is damage — right-click Half-Life › Properties › Installed Files › Verify integrity of game files to restore the originals.

Frequently asked

Do I need the full game, or does a demo work?

The full game. Mods load assets from the base installation, and a demo doesn't contain them.

Can I install a mod inside another mod's folder?

No. Each mod is a sibling of valve, never nested inside another mod. Two mods that both ship code can't be combined at all.

Are mod folder names case-sensitive?

On Windows, no. On Linux and Steam Deck, yes — -game ModName and -game modname are different there. Match the folder exactly and it works everywhere.

Will mods disable my achievements?

Mods run as separate entries and generally don't award the base game's achievements. That's a consequence of how they launch, not a penalty.

Is it safe to add an antivirus exclusion for the Half-Life folder?

Mods ship unsigned .dll files that scanners sometimes quarantine, which breaks them. If you add an exclusion, scope it to that folder only and download from the author's official page rather than a re-upload.
